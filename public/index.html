Debian and Ubuntu

curl -fsSL https://dl.shellcell.dev/apt/keys/archive-signing.gpg \
  | sudo tee /usr/share/keyrings/shellcell.gpg > /dev/null
echo 'deb [signed-by=/usr/share/keyrings/shellcell.gpg] https://dl.shellcell.dev/apt stable main' \
  | sudo tee /etc/apt/sources.list.d/shellcell.list
sudo apt-get update
sudo apt-get install snailmail

The signed-by keyring scopes that key to this repository alone, so it can never vouch for anything else on your system.

Fedora and RHEL

sudo tee /etc/yum.repos.d/shellcell.repo >/dev/null <<'REPO'
[shellcell]
name=shellcell
baseurl=https://dl.shellcell.dev/yum
enabled=1
repo_gpgcheck=1
gpgcheck=0
gpgkey=https://dl.shellcell.dev/yum/keys/yum-archive-keyring.asc
REPO
sudo dnf install snailmail

repo_gpgcheck verifies the signature over the repository metadata. gpgcheck is off because the packages themselves are not signed — that signature is made by whoever builds a package, not by the repository.

Alpine

sudo curl -fsSL -o /etc/apk/keys/alpine-signing.rsa.pub \
  https://dl.shellcell.dev/alpine/keys/alpine-signing.rsa.pub
echo https://dl.shellcell.dev/alpine | sudo tee -a /etc/apk/repositories
sudo apk add snailmail

apk finds the key by filename alone, so it must be installed under exactly that name before the repository can be used.

Helm

helm repo update
